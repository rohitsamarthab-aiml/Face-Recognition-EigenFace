Allocates an empty distance matrix `distances` of shape `(100, 300)`. Then `np.argmin(distances, axis=1)` finds the closest training index for each test face, `y_pred = y_train[nearest_indices]` assigns the predicted person ID, and `accuracy_score` + `classification_report` evaluate the `94.00%` accuracy.

            Core Equations Reference
            
The Three Pillar Equations & Symbol Definitions

            

              Every symbol in the three foundational formulas of our project defined in plain, beginner-friendly language.
            

          

        


        

          
          

            1. Covariance Eigenvalue Equation
            

              C v = λ v
            

            
    
              
  • C: Sample covariance matrix (4,096 × 4,096) measuring how pairs of pixels vary together across the 300 training faces.
    • 
              
  • v: Non-zero unit eigenvector (4,096 × 1)—a principal axis direction in pixel space (reshaped to 64 × 64, it is an Eigenface).
    • 
              
  • λ (lambda): Scalar eigenvalue (≥ 0) telling us the exact amount of variance (spread) captured along direction v.
    • 
            

          


          
          

            2. PCA Subspace Projection
            

              z = (x − μ)VT
            

            
    
              
  • x: Flattened input face row vector (1 × 4,096).
    • 
              
  • μ (mu): Mean Face row vector (1 × 4,096, pca.mean_) averaged over the 300 training faces.
    • 
              
  • (x − μ): Mean-centered face vector (X_test_centered on Line 58 of main.py).
    • 
              
  • VT: Transpose (4,096 × 100) of the 100-Eigenface matrix pca.components_.
    • 
              
  • z: Resulting compressed row vector (1 × 100) of PCA weights.
    • 
            

          


          
          

            3. Euclidean Distance in PCA Space
            

              d(x, y) = √Σ(xi − yi)2
            

            
    
              
  • x, y: Two 100-component PCA feature vectors (one test face x and one training face y).
    • 
              
  • xi − yi: Difference on the i-th principal component (difference = X_train_pca - test_face).
    • 
              
  • (xi − yi)2: Squared difference so negative and positive offsets never cancel out.
    • 
              
  • Σ & √: Sum across all i = 1..100 components followed by the square root to yield straight-line distance.
    • 
            

          

        


        
        

          
            Crucial Conceptual Distinction: 94.40% Explained Variance Retained vs. 94.00% Recognition Accuracy
          
          

            Although 94.40% and 94.00% look numerically similar in our experiment, they measure completely different mathematical properties and are specific to our Olivetti dataset split and k = 100 setting (not universal guarantees):
          

          
    
            
  • 94.40% Explained Variance Retained (Unsupervised Training Compression Quality): Equals (Σm=1..100 λm / Σj=1..4096 λj) × 100. It tells us that compressing 4,096 pixels into 100 Eigenface weights preserves 94.40% of the statistical pixel spread across the 300 training images—without looking at who the people are.
    • 
            
  • 94.00% Recognition Accuracy (Supervised Test Classification Performance): Equals (94 correct test matches / 100 total test images) × 100. It tells us how often the nearest training neighbor in 100-D PCA space has the exact same person identity label as the unseen test image.

                1. Digital Grayscale Images and Pixel Values
              

              Topic 1 of 15
            

            
    
              
  • A digital grayscale image is a 2-dimensional grid (matrix) of tiny light-intensity squares called pixels.
  • In the Olivetti Faces dataset, every photograph has a resolution of 64 rows by 64 columns (64 × 64 pixels).
  • Each pixel stores a single floating-point brightness number I(r, c) scaled between 0.0 (pure black) and 1.0 (pure white), where r is the row index (0 to 63) and c is the column index (0 to 63).
    • 
            

            

              I(r, c) ∈ [0.0, 1.0]   for   r ∈ {0, 1, …, 63},  c ∈ {0, 1, …, 63}
            

            

              Symbol Definitions: I = 64×64 image matrix; r = vertical row index; c = horizontal column index; 0.0 = black; 1.0 = white.
            

            

              Simple Worked Example: A pixel in the dark pupil of an eye might have intensity I(21, 20) = 0.12, whereas a bright pixel on the forehead might have intensity I(10, 32) = 0.84.
            

          

        
          

            

              

                2. Converting a 64 × 64 Image into a 4,096-Feature Vector
              

              Topic 2 of 15
            

            
    
              
  • Linear algebra operations (such as dot products, covariance matrices, and eigenvector projection) require each image to be represented as a 1D vector rather than a 2D square grid.
  • We flatten (unroll) the 64 × 64 image row-by-row from top to bottom: Row 0 (pixels 0..63), followed by Row 1 (pixels 64..127), down to Row 63 (pixels 4032..4095).
  • This turns one 64 × 64 image into a single row vector x of length 64 × 64 = 4,096 numerical features.
    • 
            

            

              x = [x₁, x₂, …, x₄₀₉₆] ∈ ℝ⁴⁰⁹⁶,   where index k = 64·r + c + 1
            

            

              Symbol Definitions: x = flattened 4,096-feature face vector; ℝ⁴⁰⁹⁶ = 4,096-dimensional real vector space.
            

            

              Simple Worked Example: In main.py (Line 20), X = np.asarray(faces.data, dtype=np.float64) has shape (400, 4096)—meaning 400 rows (images) and 4,096 columns (pixel features).
            

          

        
          

            

              

                3. The Olivetti Faces Dataset and the 300/100 Training-Test Split
              

              Topic 3 of 15
            

            
    
              
  • The Olivetti Faces dataset (collected at AT&T Laboratories Cambridge) contains 400 grayscale face images across 40 distinct individuals (10 photographs per person).
  • Photographs of the same person were taken at different times with varying facial expressions (smiling/not smiling, eyes open/closed), lighting conditions, and glasses.
  • In main.py (Lines 32–38), train_test_split(..., test_size=0.25, random_state=42, stratify=y) splits the 400 images into 300 training images (75%) and 100 unseen test images (25%).
  • Using stratify=y guarantees balanced class representation across all 40 people so the model is tested fairly on unseen photographs.
    • 
            

            

              |D_total| = 400   →   |D_train| = 300 (75%)   and   |D_test| = 100 (25%)
            

            

              Symbol Definitions: D_train = 300 images used to learn the Mean Face and Eigenfaces; D_test = 100 held-out images used only to test recognition accuracy.
            

            

              Simple Worked Example: Each of the 40 subjects has 10 photos total: 7 or 8 photos go into X_train (totaling 300) and 2 or 3 photos go into X_test (totaling 100).
            

          

        
          

            

              

                4. Dimensionality Reduction
              

              Topic 4 of 15
            

            
    
              
  • Working directly with 4,096 features per image is computationally expensive and suffers from redundancy because neighbouring pixels (such as adjacent cheek pixels) have nearly identical brightness.
  • Dimensionality reduction transforms high-dimensional vectors (D = 4,096) into a much smaller number of informative coordinates (k = 100) while preserving the essential structure of the data.
  • Shrinking 4,096 features to 100 components reduces the number of stored features per face by 97.56%.
    • 
            

            

              Feature Reduction (%) = ((4096 − 100) / 4096) × 100 = (3996 / 4096) × 100 = 97.5586% ≈ 97.56%
            

            

              Symbol Definitions: D = 4,096 original pixel features; k = 100 retained principal components.
            

            

              Simple Worked Example: Instead of performing 4,096 subtractions and squarings to compare two faces, the computer only performs 100—speeding up matching by more than 40×.
            

          

        
          

            

              

                5. Mean-Centering the Data
              

              Topic 5 of 15
            

            
    
              
  • Before finding principal directions of variation, we must center the dataset at the coordinate origin by subtracting the average training face (Mean Face μ).
  • The Mean Face μ is calculated by averaging all N = 300 training face vectors pixel-by-pixel.
  • Subtracting μ from every training and test vector removes the common baseline face template so PCA captures how individuals differ from the average.
    • 
            

            

              μ = (1 / N) ∑_{i=1..N} xᵢ,     x̃ᵢ = xᵢ − μ
            

            

              Symbol Definitions: N = 300 training images; μ = 4,096-dimensional Mean Face vector (pca.mean_); x̃ᵢ = mean-centered face vector.
            

            

              Simple Worked Example: In main.py (Line 58), X_test_centered = X_test - pca.mean_ explicitly subtracts the 4,096-element training mean face from every test image before projection.
            

          

        
          

            

              

                6. Variance, Covariance, Eigenvalues, and Eigenvectors
              

              Topic 6 of 15
            

            
    
              
  • Variance measures the spread of pixel brightness values around the mean along a single coordinate axis.
  • Covariance measures how two different pixel coordinates vary together across the training faces; the Covariance Matrix C collects all pairwise covariances.
  • An eigenvector v of covariance matrix C is a special unit direction that is not rotated when multiplied by C—it is only scaled by a scalar factor λ called its eigenvalue.
  • Geometrically, eigenvectors point along the principal axes of the data cloud, and each eigenvalue λ measures the exact amount of variance captured along its eigenvector.
    • 
            

            

              C v = λ v     where   C = (1 / (N − 1)) X̃ᵀ X̃
            

            

              Symbol Definitions: C = 4,096 × 4,096 sample covariance matrix; v = 4,096-dimensional unit eigenvector (principal axis); λ = scalar eigenvalue (variance along v).
            

            

              Simple Worked Example: If a 2×2 covariance matrix is C = [[4, 4], [4, 4]], multiplying by v₁ = [1, 1]ᵀ gives [8, 8]ᵀ = 8 v₁, so v₁ is an eigenvector with eigenvalue λ₁ = 8.
            

          

        
          

            

              

                7. Principal Component Analysis (PCA)
              

              Topic 7 of 15
            

            
    
              
  • Principal Component Analysis (PCA) is an unsupervised linear algebra method that diagonalizes the covariance matrix C (or performs Singular Value Decomposition on X̃) to find a new set of mutually perpendicular (orthonormal) coordinate axes.
  • The new axes—called Principal Components—are sorted in descending order of their eigenvalues: λ₁ ≥ λ₂ ≥ … ≥ λ_D ≥ 0.
  • Because the axes are orthogonal (vᵢ · vⱼ = 0 for i ≠ j), the projected coordinates are completely uncorrelated.
    • 
            

            

              vᵢᵀ vⱼ = 1 (if i = j)   and   0 (if i ≠ j),   with   λ₁ ≥ λ₂ ≥ … ≥ λ_k
            

            

              Symbol Definitions: vᵢ, vⱼ = principal component basis vectors; λᵢ = variance explained by the i-th principal component.
            

            

              Simple Worked Example: In main.py (Lines 49–55), PCA(n_components=100, svd_solver='full', whiten=False) computes the exact SVD of the centered 300 × 4,096 training matrix.
            

          

        
          

            

              

                8. Principal Components and the Selection of 100 Components
              

              Topic 8 of 15
            

            
    
              
  • With 300 training images in ℝ⁴⁰⁹⁶, there are at most 300 non-zero eigenvalues, and the vast majority of facial structure is concentrated in the first 100 components.
  • Choosing k = 100 components strikes an ideal balance: it discards 3,996 low-variance noise directions while keeping 94.40% of the total dataset variance.
  • The retained eigenvectors are stored as the 100 rows of pca.components_ (matrix V of shape 100 × 4,096).
    • 
            

            

              V = [v₁, v₂, …, v₁₀₀]ᵀ ∈ ℝ¹⁰⁰ˣ⁴⁰⁹⁶
            

            

              Symbol Definitions: V = matrix whose 100 rows are the top 100 unit eigenvectors (pca.components_ in scikit-learn).
            

            

              Simple Worked Example: Component 1 (v₁) captures global illumination and vertical face symmetry, whereas later components capture finer details like eyebrow thickness and glasses.
            

          

        
          

            

              

                9. Explained Variance and Its Interpretation
              

              Topic 9 of 15
            

            
    
              
  • Each component's explained variance ratio is its eigenvalue λ_m divided by the sum of all eigenvalues ∑ λ_j.
  • Cumulative explained variance for k = 100 components is the sum of the top 100 explained variance ratios multiplied by 100%.
  • In our Python experiment, retaining 100 components yields 94.40% explained variance—meaning 94.40% of the total statistical spread across the 300 training faces is preserved.
    • 
            

            

              Explained Variance Retained (%) = ( ∑_{m=1..100} λ_m / ∑_{j=1..D} λ_j ) × 100 = 94.40%
            

            

              Symbol Definitions: λ_m = eigenvalue of component m; pca.explained_variance_ratio_ = array of ratios λ_m / ∑ λ_j.
            

            

              Simple Worked Example: In main.py (Line 70), variance = np.sum(pca.explained_variance_ratio_) * 100 computes 94.40%, and Line 132 plots np.cumsum(pca.explained_variance_ratio_).
            

          

        
          

            

              

                10. Eigenfaces and the Mean Face
              

              Topic 10 of 15
            

            
    
              
  • Because the Mean Face μ and each eigenvector v_m have exactly 4,096 entries, we can reshape each one back into a 64 × 64 pixel grid and view it as a grayscale image.
  • When reshaped to 64 × 64, the eigenvectors look like ghostly facial templates and are therefore called Eigenfaces (Turk & Pentland, 1991).
  • Every face in the dataset can be approximated as the Mean Face plus a weighted sum of these 100 Eigenfaces.
    • 
            

            

              x ≈ μ + z₁ v₁ + z₂ v₂ + … + z₁₀₀ v₁₀₀ = μ + ∑_{m=1..100} z_m v_m
            

            

              Symbol Definitions: μ = Mean Face (64×64); v_m = m-th Eigenface (64×64); z_m = scalar weight (coordinate) of the face along Eigenface m.
            

            

              Simple Worked Example: In main.py (Lines 109–127), axes[0, 0] displays pca.mean_.reshape(64, 64) and the next 9 panels display pca.components_[0..8].reshape(64, 64), saved as outputs/eigenfaces.png.
            

          

        
          

            

              

                11. Projection into PCA Space
              

              Topic 11 of 15
            

            
    
              
  • To project a 4,096-dimensional face row vector x into the 100-dimensional PCA subspace, we first subtract the Mean Face μ and then multiply by Vᵀ (taking the dot product with each of the 100 Eigenfaces).
  • This transforms a 4,096-pixel image x into a compact 100-element weight vector z = [z₁, z₂, …, z₁₀₀].
  • In main.py (Lines 58–63), this exact formula is implemented manually for the test set!
    • 
            

            

              z = (x − μ) Vᵀ     where   z_m = ∑_{p=1..4096} (x_p − μ_p) V_{m,p}
            

            

              Symbol Definitions: x = 1 × 4,096 input face vector; μ = 1 × 4,096 Mean Face (pca.mean_); V = 100 × 4,096 Eigenface matrix (pca.components_); Vᵀ = 4,096 × 100 transpose; z = 1 × 100 projected PCA weight vector.
            

            

              Simple Worked Example: In main.py (Lines 58–63): X_test_centered = X_test - pca.mean_, followed by np.sum(row * pca.components_, axis=1), computes z = (x − μ)Vᵀ row-by-row.
            

          

        
          

            

              

                12. Euclidean Distance and Its Formula
              

              Topic 12 of 15
            

            
    
              
  • Once all training and testing faces are projected into ℝ¹⁰⁰, we measure how similar two faces are by computing the straight-line (L2 Euclidean) distance between their 100-element PCA weight vectors.
  • For two vectors x = [x₁, …, x₁₀₀] and y = [y₁, …, y₁₀₀], we subtract corresponding coordinates, square each difference (so negative and positive differences both contribute positively), sum all 100 squares, and take the square root.
    • 
            

            

              d(x, y) = √( ∑_{i=1..k} (xᵢ − yᵢ)² )
            

            

              Symbol Definitions: d(x, y) = Euclidean distance (≥ 0); xᵢ = i-th PCA weight of the test face; yᵢ = i-th PCA weight of a training face; k = 100 components.
            

            

              Simple Worked Example: For 3D vectors A = [1, 2, 3] and B = [4, 5, 6]: differences are [−3, −3, −3], squared differences are [9, 9, 9], sum is 27, and d(A, B) = √27 ≈ 5.1962.
            

          

        
          

            

              

                13. Nearest-Neighbour Classification
              

              Topic 13 of 15
            

            
    
              
  • For a given test face vector z_test, we calculate its Euclidean distance d(z_test, z_train,j) to all 300 training faces (j = 0, 1, …, 299).
  • The 1-Nearest Neighbour (1-NN) classifier finds the index j* with the smallest Euclidean distance using np.argmin.
  • The predicted identity for the test face is simply the person label y_train[j*] of that closest training face.
    • 
            

            

              j* = argmin_{j ∈ {0,…,299}} d(z_test, z_train,j),     ŷ_test = y_train[j*]
            

            

              Symbol Definitions: j* = index of closest training face (nearest_indices); ŷ_test = predicted person ID (y_pred).
            

            

              Simple Worked Example: In main.py (Lines 89–91), nearest_indices = np.argmin(distances, axis=1) finds j* for all 100 test faces, and y_pred = y_train[nearest_indices] assigns their predicted person IDs.
            

          

        
          

            

              

                14. Accuracy, Precision, Recall, F1-Score, and Classification Reports
              

              Topic 14 of 15
            

            
    
              
  • Recognition Accuracy measures the overall percentage of test images classified with the correct person identity: (Correct Predictions / Total Test Images) × 100 = (94 / 100) × 100 = 94.00%.
  • Precision for Person c = TP / (TP + FP): out of all test photos the model claimed were Person c, what fraction actually belonged to Person c?
  • Recall for Person c = TP / (TP + FN): out of all actual test photos of Person c, what fraction did the model successfully recognize?
  • F1-Score = 2 · (Precision · Recall) / (Precision + Recall): the harmonic mean balancing Precision and Recall for each class in classification_report.
    • 
            

            

              Accuracy = (94 / 100) × 100 = 94.00%   |   F1 = 2 · (Precision · Recall) / (Precision + Recall)
            

            

              Symbol Definitions: TP = True Positives; FP = False Positives; FN = False Negatives.
            

            

              Simple Worked Example: In main.py (Lines 93–99), accuracy_score(y_test, y_pred) returns 0.94 (94.00%) and classification_report(y_test, y_pred, zero_division=0) prints the per-person metrics.
            

          

        
          

            

              

                15. Advantages, Limitations, Applications, and Privacy Considerations
              

              Topic 15 of 15
            

            
    
              
  • Advantages: Unsupervised compression (97.56% fewer features), fast Euclidean matching, low memory footprint, and automatic filtering of high-frequency pixel noise.
  • Limitations: Sensitive to large changes in head pose, extreme lighting shadows, or background clutter; captures only linear correlations; nearest-neighbour distance is not a calibrated probability.
  • Applications: Biometric access control Research, image compression, medical imaging feature extraction, and preprocessing for machine learning classifiers.
  • Privacy & Ethics Considerations: Facial recognition systems process sensitive biometric data. Real-world deployment requires informed consent, bias auditing across demographic groups, secure storage, and strict compliance with data-protection laws.
    • 
            

            

              Compression Ratio = 4096 / 100 = 40.96× smaller representation per face
            

            

              Symbol Definitions: 4,096 = original pixel count; 100 = compressed Eigenface weight count.
            

            

              Simple Worked Example: While 94.00% accuracy is achieved on the controlled Olivetti dataset (cropped 64×64 studio faces), real-world wild environments require alignment and ethical safeguards.
